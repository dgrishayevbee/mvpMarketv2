# mvpMarket v2 — Архитектура прототипа

Вторая итерация прототипа. Первая версия — `dgrishayevbee/mvpMarket`,
её архитектурный документ остаётся там и описывает старую дизайн-систему.

## 1. Суть проекта

B2B маркетплейс-прототип. Единственный поставщик товаров в каталоге — сама
платформа. Роли покупатель/продавец переключаются как мок, без разграничения
прав на сервере. Без бэкенда, без БД, без реальной авторизации.

## 2. Отношение к первой версии

Переносится из v1 без изменений:

- слой состояния — все контексты в `src/context/`;
- `useLocalStorage`;
- контент главной — `src/data/siteContent.js`;
- карта роутов;
- конфигурация Vite и Vercel.

Пишется заново под новую дизайн-систему:

- `src/styles/tokens.css` — целиком из нового экспорта;
- UI-кит;
- вёрстка и разметка всех страниц;
- все CSS-файлы.

Из v1 не копируется CSS. Причина: перенесённая вёрстка тянет за собой
допущения старых токенов (размеры, ритм, радиусы) и новая ДС получается
натянутой на старый скелет.

## 3. Стек

React 19, Vite, React Router 7. Состояние — React Context поверх
localStorage, без Redux и без сервера. Стили — обычный CSS с переменными,
по файлу на компонент.

## 5. Состояние приложения

Провайдеры вложены в `src/App.jsx` в порядке: Auth → Content → Products →
Cart → Favorites → Orders → UI.

- **AuthContext** — мок-авторизация, B2B-регистрация по ЭЦП (компания, БИН,
  подписант), режим продавца.
- **ContentContext** — контент главной поверх дефолтов из `siteContent.js`;
  сохранённая копия мержится с дефолтами, а не заменяет их, и версия
  контента защищает от устаревшей копии в браузере.
- **ProductsContext** — товары, выведенные из контента.
- **CartContext** — единая корзина для всех точек добавления.
- **FavoritesContext**, **OrdersContext** — избранное и заказы.
- **UIContext** — состояние оверлеев. Сейчас содержит набор из v1
  (корзина, фильтры, быстрый просмотр); пересматривается, когда станет
  понятен набор оверлеев новой ДС.

Все ключи localStorage — с префиксом `mvpmarket:`.

## 6. Вёрстка / адаптив

Фокус — десктоп. Мобильные брейкпоинты добавляются позже, поэтому
layout- и контент-компоненты разделяются сразу.

### 6.1. Грабли вёрстки (проверять перед пушем)

Раздел перенесён из v1: ошибки в нём про CSS и flex, а не про дизайн-систему,
поэтому остаются актуальными. Пополняется каждый раз, когда правка ломает
страницу на живом сайте.

- **Центрирование блока внутри flex-колонки.** Если контейнер — это
  `display: flex; flex-direction: column`, то все его секции — flex-элементы.
  Связка `max-width: N` + `margin-inline: auto` на таком элементе отключает
  растягивание (`align-self: stretch`) и превращает его в shrink-to-fit блок:
  ширина схлопывается до контента, а grid-колонки `1fr` — до min-content.
  Так же ведут себя `align-self: center` и `width: fit-content`.
  Правильно — задавать **явную** ширину: `width: min(100%, N px)` плюс
  `margin-inline: auto`.
- **Прод-ветка = живой сайт.** Пуш в `main` сразу уходит в Vercel, поэтому
  layout-правку нельзя пушить «на глаз» — сначала проверка.

**Проверка layout-правки перед пушем** (обязательна, если менялись
`width`/`max-width`/`margin`/`display`/`grid-template`/`flex`):

1. `npm run dev`, открыть изменённую страницу.
2. Снять скриншоты на широком экране (~1920px) и на ~1280px — именно на
   широком вылезают ошибки центрирования и схлопывания.
3. Сверить: ширина карточек не изменилась (если задача была только про
   расположение), нет горизонтального скролла, поля слева/справа соразмерны.
4. Только после этого коммит и пуш.

В удалённой сессии Claude Code шаги 1-2 делаются без установки зависимостей:
Chromium и Playwright уже стоят в окружении
(`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`), достаточно поднять dev-сервер
и снять скриншот скриптом во временной папке.

## 7. Дизайн-система

Не подключена. `src/styles/tokens.css` — нейтральная заглушка с минимальным
набором переменных, которого хватает для `global.css` и заглушек экранов.
Значения намеренно невыразительные: пока сайт выглядит уродливо, видно, что
настоящая ДС ещё не пришла.

Когда экспорт появится: `tokens.css` переписывается целиком, компоненты не
трогаются — они читают переменные, а не значения. Шрифты подключаются в
`index.html` (там уже стоит комментарий-место).

## 8. Запуск и деплой

```bash
npm install
npm run dev
```

Прод — Vercel, ветка `main`, автодеплой по пушу. `vercel.json` даёт SPA
fallback на `index.html`.
